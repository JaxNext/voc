## 3. Configuration Details

### 3.1 Nuxt & Nitro (`nuxt.config.ts`)

Updated `nuxt.config.ts` to register modules and platform presets:

- **Modules registered**:
  - `@nuxt/ui` (v4 UI components & Tailwind CSS v4)
  - `@nuxtjs/supabase` (Auth & direct PostgREST client)
  - `@vite-pwa/nuxt` (PWA manifest, service worker & offline support)
- **CSS entry (`app/assets/css/main.css`)**:
  - Nuxt UI v4 (Tailwind v4) does not inject styles by itself; the app stylesheet must be registered explicitly via `css: ['~/assets/css/main.css']` in `nuxt.config.ts`.
  - The file contains exactly two imports: `@import "tailwindcss";` and `@import "@nuxt/ui";` (the latter injects Nuxt UI's design tokens & component styles, e.g. the `bg-elevated` / `text-muted` semantic colors).
  - Missing this entry caused every page to render as unstyled native HTML (browser defaults) — caught during first visual pass of the app shell.
- **Font providers**:
  - `fonts.providers.google` / `googleicons` are set to `false`: `fonts.google.com` is unreachable from the dev network, and `unifont`'s fetch retries stalled every dev-server start by ~40s. With the providers disabled, the UI falls back to system fonts instantly.
- **Deployment preset**:
  - `nitro.preset: 'cloudflare_pages'` with `nitro.cloudflare.nodeCompat: true` for full compatibility with edge runtime APIs.
- **Supabase configuration**:
  - `redirect: false` (auth redirects managed explicitly in `app/middleware/auth.global.ts`).
  - `cookieOptions: { secure: process.env.NODE_ENV === 'production' }`.
  - `runtimeConfig` holding `supabaseServiceRoleKey` (server-private) and public keys (`supabaseUrl`, `supabaseAnonKey`).
- **PWA Manifest**:
  - Name: `Voc — Vocabulary Review`
  - Theme / Background Color: `#0f172a`
  - Display: `standalone`
  - Icons registered: `/icons/icon-192.png`, `/icons/icon-512.png`, `/icons/icon-512-maskable.png`.
