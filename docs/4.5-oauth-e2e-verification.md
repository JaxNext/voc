## Interactive runbook (requires a browser + a Voc account)

Voc dev server NOT required — the consent UI is live on production. Only the mock runs locally.

1. **Happy path:** `node scripts/oauth-mock-client.mjs` → open `http://localhost:5000/` →
   click **Sign in with Voc** → log in (Voc) → consent page shows "Test App … requests
   access" → **Approve** → land on the mock's result page: token exchange HTTP 200,
   claims include `client_id`, PostgREST read HTTP 200, write HTTP 201 (a new
   `OAuth E2E write test — …` record appears in the Voc app).
2. **Already-consented shortcut:** click Sign in with Voc again → no consent UI, straight
   to the result page (Supabase stores the consent grant).
3. **Deny path:** revoke the grant (or use a second browser profile / incognito), run the
   flow again → **Deny** → mock shows `error=access_denied` from the redirect URI.
4. **RLS isolation:** run the flow as user A (note the read table), then log out, run as
   user B → A's written record must NOT appear in B's read table; B's write lands only in
   B's scope.
5. **Missing `authorization_id`:** while logged in, open
   `https://voc-9d5.pages.dev/oauth/consent` → error alert ("Missing authorization
   request…") instead of a crash.
