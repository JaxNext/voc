## Design Decisions

1. The constant lives beside `PUBLIC_AUTH_PATHS` (the established single source of truth
   shared by the guard and the app shell) so the middleware, login redirect handling, and
   nav-hiding logic all reference one value.
2. Not adding it to `PUBLIC_AUTH_PATHS` keeps the guard treating `/oauth/consent` as
   protected: unauthenticated visitors are bounced to `/login` with the `authorization_id`
   preserved (next 4.3 items).
3. The open-redirect guard is a named export on `routes.ts` (auth-conventions module) and is
   shared by login _and_ register; it rejects external URLs, protocol-relative `//`,
   backslash paths (browser-normalizable to external origins), and non-string input
   (repeated query params). Strict-fail: anything unrecognized falls back to `/`.
4. The login page's "Create one" link preserves the pending `redirect` into
   `/register?redirect=…` so the consent flow also survives a login → registration switch.
5. Registration's preserve-and-return extends through the email-verification detour:
   register passes `redirect` into both `/verify-email?…` navigation and `emailRedirectTo`
   (Supabase preserves extra params and appends the token), and verify-email honors it in
   both success branches — otherwise email-confirmed signups would silently drop the flow.

6. `app.vue` renames `isPublicRoute` to `isFullscreenRoute`: the consent screen shares the
   _presentation_ of the auth screens (own full-screen layout, no bottom nav) without
   sharing their _auth semantics_ — `PUBLIC_AUTH_PATHS` is untouched, so the guard still
   requires a session on `/oauth/consent`.
