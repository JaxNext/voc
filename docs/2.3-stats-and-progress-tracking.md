## 2. API Design Decisions

- **Counts aggregate over `review_states`, not `records.learning_status`.** The grading route (`grade.post.ts`) updates `review_states.status` but never syncs `records.learning_status`, so a records-based count would read stale zeros forever. This follows [tech-design.md §7](./tech-design.md) ("Total / learning / mastered counts (aggregate over `review_states`)").
- **`learning` = `new` + `learning` (not yet mastered).** A `review_states` row starts as `new` and is due immediately (`next_review_at` defaults to `now()`), so never-reviewed records are already in the active loop. With this definition the three KPI cards reconcile (`Total ≈ Learning + Mastered`) instead of leaving the `new` bucket invisible.
- **`dueToday` rides along in the response**, using the exact same predicate as `GET /api/review/session` (`next_review_at <= now`, status not mastered). The stats page needs it for its "due today" callout; computing it here mirrors the session route's `totalDue` precedent and saves a second request.
- **Timezone is a query parameter:** `?tz=` takes an IANA name, validated with an `Intl.DateTimeFormat` construction — invalid names get a clean `400`, missing falls back to `UTC`. Day keys are produced via `formatToParts` (immune to runtime locale format quirks) and the previous-day walk uses UTC-anchored arithmetic, so month, leap-year, and DST boundaries stay correct.
- **Streak semantics:** the run ends at today or yesterday — "not reviewed _yet_ today" does not break the streak, but the first missing day before that does. Zero activity → 0.
- **Reads use the caller's JWT** (`serverSupabaseClient`), so RLS scopes all three tables to the owner — no service key on this route (architecture rule 2). The five queries (4 head-counts + event timestamps) run in `Promise.all`.
- **Event aggregation happens in JS** on a single fetched `reviewed_at` column: PostgREST has no `date_trunc` grouping, and personal-scale volumes (tens of events/day) make a full column scan acceptable. If volume ever matters, a Postgres RPC (`date(reviewed_at) at time zone …` group-by) is the upgrade path.
- **Pure math lives in `server/utils/stats.ts`** with the route as thin glue — same testability split as `srs.ts`.
- **Known build warning (pre-existing, not introduced here):** Rollup warns about the `#supabase/server` barrel re-export of `serverSupabaseClient`; the identical warning already fired for `session.get.ts` before this task. The build succeeds; deep-importing the module file is the fix if it ever matters.

## 3. Page Design Decisions (`stats.vue`)

- **One request feeds the whole page.** `onMounted` fetches `/api/stats` (client-only, same pattern as the review index) passing `Intl.DateTimeFormat().resolvedOptions().timeZone` as `?tz=` so the server's streak/weekly day boundaries match the device calendar. Refetching on every mount means finishing a review session and navigating back shows fresh numbers immediately.
- **"Start review" CTA deep-links to `/review/session`.** The session page rebuilds a queue via `ensureQueue` on mount, so the CTA goes straight into the flashcard flow — one tap, no intermediate stop at the review index. When `dueToday === 0` the callout renders a muted "All caught up" state (🎉, matching the review pages' zero-state styling) without a CTA.
- **Streak badge doubles as the zero-state.** Active streak: flame icon + "N-day streak" in `text-warning`; zero streak: muted "No streak yet — review today to start one", which nudges the habit loop instead of displaying a demotivating "0-day".
- **Weekly histogram is plain markup** (no chart library): 7 flex columns against a fixed-height track, bar height proportional to the week max (10% floor for nonzero days), 4px stub for zero days, narrow weekday labels under each bar (`M T W T F S S` per the §6.7 wireframe), today highlighted. Each bar carries `title`/`aria-label` ("2026-09-14: 12 reviews") for hover and screen readers.
- **KPI accents:** Total `text-highlighted`, Learning `text-primary`, Mastered `text-success` — semantic Nuxt UI tokens consistent with the rest of the app; `tabular-nums` keeps the digits aligned like the session summary.
- **`describeError` is shared, not duplicated.** The composable's private ofetch-message mapper was exported and reused, so a 401 on the stats fetch renders the same "Your session has expired — sign in again" copy as the review pages.
