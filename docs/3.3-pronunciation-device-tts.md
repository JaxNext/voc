## 2. Design Decisions

- **No server, no third-party service.** Pronunciation is pure client-side Web Speech API (`window.speechSynthesis`) — in-app, no network dependency at playback time (user preference: in-app solutions over external servers). The Nitro layer stays untouched, consistent with the "thin Nitro" architecture rule.
- **Voice choice is per-device by design.** Installed voices differ per platform (Samantha on iOS, Google US English on Chrome, Microsoft voices on Windows/Edge), so a Supabase-synced preference could not resolve reliably across devices. The pick persists in `localStorage` under `voc:tts-voice` (the `SpeechVoiceOption` triple: `uri` + `lang` + `name`).
- **Resolution chain on `speak()`:** saved `voiceURI` if still installed → first `en-*` voice → `utterance.lang = 'en-US'` fallback. Resolution reads fresh state each call (not the reactive list), so a deleted voice degrades gracefully without any sync logic.
- **SSR safety via two paths.** The composable checks `typeof window !== 'undefined' && getSynth()`. Inside a component instance it defers state population to `onMounted` so the client-only `supported` flag and voice list land after hydration (SSR rendered the button-less markup — no hydration mismatch); when called bare (tests) it refreshes synchronously. `onUnmounted` cancels playback and detaches the listener.
- **Async voice loading.** `getVoices()` returns `[]` on the first call in Chrome until the engine is ready, so the composable attaches a `voiceschanged` listener that refills the reactive `englishVoices` list; the Settings picker renders "Automatic" only until voices arrive.
- **Front stays silent.** The flashcard front is a production-recall prompt — audio there would leak a recall hint — so the 🔊 button only exists on the revealed back. On card advance the `record.id` watcher calls `stop()` so audio never bleeds into the next card.
- **Active-playback feedback.** The composable exposes a reactive `speaking` flag (set on `speak()`, cleared on the utterance's `onend`/`onerror`, on `stop()`, and on unmount — `cancel()` alone does not reliably fire `onend` across engines). Both 🔊 buttons (record detail and flashcard back) switch from `neutral` to `primary` while speaking so users can see playback in progress.
- **Hidden when unsupported.** Every 🔊 affordance and the Settings row itself (`v-if="supported"`) disappear on engines without `speechSynthesis`; no dead UI.
- **Picker filters to English voices** (`lang` starts with `en` — the app's target language) with an explicit "Automatic" option representing the resolution chain's first-English-voice default. That option uses a `__automatic__` sentinel value rather than `''` — Reka UI's `<SelectItem>` (Nuxt UI v4) throws at mount for empty-string values, since `""` is reserved for "clear to placeholder".
- **Playback speed is a persisted preference**, not a per-utterance parameter: `setRate` clamps to 0.5–2× and writes `voc:tts-rate` immediately (slider feels live), while `speak()` re-reads the stored value each call — same fresh-read pattern as the voice resolution, so detail/flashcard/Test playback all honor the latest setting with zero sync logic.
