## 2. Design Decisions

- **Profile data comes straight from the auth user** — `useSupabaseUser()` supplies `email` and `created_at` ("Member since September 2026"); no profile table exists in the schema (emails-auth MVP), so there is nothing else to fetch (architecture rule 4: identity from the session, never from client input).
- **Logout per the plan:** `supabase.auth.signOut()` on the [@supabase/ssr](https://supabase.com/docs/guides/auth/server-side)-backed client (module v2) clears the HttpOnly cookie session plus local session storage; the page then routes to `/login` explicitly. The global guard would also intercept any subsequent navigation, so both layers agree. The button shows a loading state and recovers with a toast on failure (non-destructive action — no confirmation, unlike record deletion).
- **Mock-faithful placeholders:** `Data export (JSON)` and `Change password` render as disabled "Coming soon" rows — export is planned for 3.1 and in-app password change is not in any phase (recovery is covered by the reset-password flow); rendering them communicates the roadmap without dead links. `About` (no content defined) is omitted.
- **Rows as a grouped list card** (`bg-elevated`, full-row tap targets with chevron), matching the bottom-nav tab "Me" and the compact mobile language used across `records/*` and `tags.vue`.
