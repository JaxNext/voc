## Design Decisions

1. **Logic in a composable, page stays thin** — matches the project's established pattern
   (cf. `useReview`): the vitest setup has no Nuxt environment, so Nuxt auto-imports
   (`useRoute`, `useSupabaseClient`, `navigateTo`) are stubbed with `vi.stubGlobal` globals
   and the SDK contract is simulated with typed `vi.fn`s. All 4.4 test requirements are
   covered at the composable level; the page only renders state.
2. **`skipBrowserRedirect: true` on approve/deny** — the SDK would otherwise navigate on
   its own; the composable follows `data.redirect_url` explicitly with
   `navigateTo(..., { external: true })` (design §7).
3. **Union narrowing via `'authorization_id' in data`** — `getAuthorizationDetails` returns
   `OAuthAuthorizationDetails` (consent needed) or `OAuthRedirect` (already consented);
   types are imported from `@supabase/supabase-js`, which re-exports `@supabase/auth-js`.
4. **`pendingDecision` ref** — disables both buttons and shows a spinner on Approve while
   the round-trip is in flight; reset when the SDK returns an error so the user can retry.
5. Scope list is rendered with `i-lucide-check` icons consistent with the app's icon usage;
   the redirect URI is shown as plain text so the user can see where the client sends them.
