## Design Decisions

1. **Upgrade supabase-js instead of the direct-HTTP fallback.** `@nuxtjs/supabase@2.0.10`
   (installed, also latest) declares `@supabase/supabase-js: ^2.112.2` as its own dependency,
   so `2.116.0` stays inside the module's supported range — no module upgrade or peer conflict.
2. **API verified against the installed typings** (`@supabase/auth-js@2.116.0`, which
   supabase-js 2.116.0 pins):
   - `supabase.auth.oauth: AuthOAuthServerApi` namespace exists on the auth client
     ("Used to implement the authorization code flow on the consent page").
   - `oauth.getAuthorizationDetails(authorizationId)` returns
     `RequestResult<OAuthAuthorizationDetails | OAuthRedirect>` — narrow with
     `'authorization_id' in data` to distinguish consent-needed from already-consented
     (the union matches design doc §7 step 3).
   - `oauth.approveAuthorization(id, { skipBrowserRedirect? })` and
     `oauth.denyAuthorization(id, { skipBrowserRedirect? })` → `RequestResult<OAuthRedirect>`
     with `redirect_url`.
   - **Behavior note:** approve/deny **auto-redirect the browser by default**
     (`skipBrowserRedirect: false`). The consent page should either let the SDK redirect or
     pass `skipBrowserRedirect: true` and navigate itself; design doc §7 updated accordingly.
   - Extra capability discovered: the namespace also exposes listing/revoking the user's
     OAuth grants (`OAuthGrant[]` with `client`, `scopes`, `granted_at`) — future "connected
     apps" management UI in Settings, deliberately out of scope for now.
3. `OAuthAuthorizationDetails` also carries `user: { id, email }` and a space-separated
   `scope` string, matching the consent UI requirements in design §7.

### Site URL decision (second 4.1 item)

- **Production origin confirmed:** `https://voc-9d5.pages.dev` (live, HTTP 302 → app).
- **Sequencing (user decision):** keep `http://localhost:3000` as Site URL through local
  development and consent testing (4.2–4.5 local runs). The consent target is always
  `Site URL + Authorization Path`, so localhost Site URL is exactly what enables local
  consent E2E — no temporary switching needed.
- **Switch to production as the final 4.5 step** (added to dev-plan 4.5): Site URL →
  `https://voc-9d5.pages.dev` (no trailing slash), plus `http://localhost:3000/**`
  (+ other dev ports such as `:3004`) in the Redirect URLs allowlist so regular
  login/verify/reset flows keep working against localhost afterwards.
- **Known trade-off while Site URL is localhost:** Supabase auth emails
  (verification/reset) link to localhost — fine while testing from the dev machine;
  do not on-board real third-party clients until the switch is done.
