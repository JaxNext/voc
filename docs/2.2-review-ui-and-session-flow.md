## 2. Design Decisions

- **Shared state in `useState`** under four keys (`voc-review-queue`, `-total-due`, `-index`, `-results`): the `/review` index builds the queue, `/review/session` consumes it card by card, and the summary screen reads the results — state must survive the client-side navigation between them. `loading`/`grading`/`error` are per-consumer local refs (transient request state).
- **API sync via global `$fetch`**: the `@nuxtjs/supabase` module attaches the session cookie automatically, so both Nitro routes (`GET /api/review/session?limit=`, `POST /api/review/grade`) authenticate without extra headers. One round-trip per graded card.
- **Advance-on-confirm**: `currentIndex` increments only after the server returns a `GradeResult`. A failed POST keeps the current card on screen for retry — consistent with the non-atomic grade route caveat in [2.1-srs-and-server-routes.md §3](./2.1-srs-and-server-routes.md) (a retry re-grades from the fresh server state).
- **Type-only cross-boundary imports**: `ReviewSession`/`ReviewSessionItem`/`GradeResult` are re-exported (as types) from the server route files (`~~/server/api/review/*.get.ts`), keeping a single source of truth without pulling server runtime code into the client bundle. `DEFAULT_QUEUE_SIZE = 10` mirrors the server's `DEFAULT_SESSION_SIZE` as a value, since importing values would cross the bundle boundary.
- **`ensureQueue(limit)`** handles deep links and full page reloads on `/review/session` (in-memory `useState` is lost): it rebuilds a queue only when none is active.
- **`exitSession()` clears the queue but keeps `totalDue`**: ungraded items remain due, so the index badge stays honest. The summary computed exposes per-grade counts, `graded`, `mastered` (from `GradeResult.mastered`), and `newCount` (cards entering with status `new`).
- **`describeError`** maps ofetch `FetchError` payloads to user-presentable messages, with a dedicated 401 message ("Your session has expired — sign in again").
- **Testability**: `computed`/`ref` are imported explicitly from Vue, so the test suite only has to stub the Nuxt auto-imports `useState` (keyed ref store) and `$fetch` (a `vi.fn` speaking the routes' contract) — no Nuxt runtime needed.
