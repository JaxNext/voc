## 2. Spec Change: Flashcard Direction (CN → EN, production recall)

The original [product-design.md](./product-design.md) §3.5 sketch was recognition-oriented: show the English content, recall the meaning. The founder's actual pain point is **production** — knowing the Chinese meaning of a thought but being unable to produce the natural English expression. Per decision on 2026-09-14, the flashcard direction is reversed:

- **Front**: the meaning, plus the type badge (Word/Phrase/Sentence) as a disambiguation hint; button reads "Show expression".
- **Back (on reveal)**: the recorded content — the exact expression the user saved — plus tags and source for context. Grade prompt: "Could you express it?".
- **Rationale**: trains active recall of the English expression (the core value loop); harder grading is _correct_ — unproducible items stay due more often, which is the SRS doing its job.
- **Known trade-off**: one meaning can map to several valid English expressions. Self-grading stays subjective (recalling a different-but-correct expression → `Know` is acceptable); showing the recorded version on reveal ensures the saved expression is always reinforced.
- **Scope**: client-side presentation only — `review_states`, both review routes, and `useReview` are direction-agnostic. Specs updated in product-design.md §3.5 + §6.5 and development-plan.md §2.2.

## 3. Design Decisions

- **Shared state in `useState`** under four keys (`voc-review-queue`, `-total-due`, `-index`, `-results`): the `/review` index builds the queue, `/review/session` consumes it card by card, and the summary screen reads the results — state must survive the client-side navigation between them. `loading`/`grading`/`error` are per-consumer local refs (transient request state).
- **API sync via global `$fetch`**: the `@nuxtjs/supabase` module attaches the session cookie automatically, so both Nitro routes (`GET /api/review/session?limit=`, `POST /api/review/grade`) authenticate without extra headers. One round-trip per graded card.
- **Advance-on-confirm**: `currentIndex` increments only after the server returns a `GradeResult`. A failed POST keeps the current card on screen for retry — consistent with the non-atomic grade route caveat in [2.1-srs-and-server-routes.md §3](./2.1-srs-and-server-routes.md) (a retry re-grades from the fresh server state).
- **Type-only cross-boundary imports**: `ReviewSession`/`ReviewSessionItem`/`GradeResult` are re-exported (as types) from the server route files (`~~/server/api/review/*.get.ts`), keeping a single source of truth without pulling server runtime code into the client bundle. `DEFAULT_QUEUE_SIZE = 10` mirrors the server's `DEFAULT_SESSION_SIZE` as a value, since importing values would cross the bundle boundary.
- **`ensureQueue(limit)`** handles deep links and full page reloads on `/review/session` (in-memory `useState` is lost): it rebuilds a queue only when none is active.
- **`exitSession()` clears the queue but keeps `totalDue`**: ungraded items remain due, so the index badge stays honest. The summary computed exposes per-grade counts, `graded`, `mastered` (from `GradeResult.mastered`), and `newCount` (cards entering with status `new`).
- **`describeError`** maps ofetch `FetchError` payloads to user-presentable messages, with a dedicated 401 message ("Your session has expired — sign in again").
- **Testability**: `computed`/`ref` are imported explicitly from Vue, so the test suite only has to stub the Nuxt auto-imports `useState` (keyed ref store) and `$fetch` (a `vi.fn` speaking the routes' contract) — no Nuxt runtime needed.
- **Flashcard is presentational** (same pattern as RecordCard): `item` in, `grade` out — the session page owns the queue via `useReview` and turns events into API calls, keeping the component testable without Nuxt and reusable. A `grading` prop disables all buttons while the POST is in flight (retry-safe: a failed grade keeps the same record, so the card stays revealed instead of resetting).
- **CSS 3D flip without fixed heights**: both faces are stacked in one grid cell (`grid-area: 1/1`) inside a `preserve-3d` container with hidden backfaces; the container rotates 180° on reveal, so card height always follows the taller face (no absolute positioning, no clipping). Honors `prefers-reduced-motion`. The card resets face-down via a `watch` on `record.id` (component instances are reused between cards).
- **Grade buttons** follow the wireframe order `Forgot / Hazy / Know / Easy` with SRS-conventional colors (`error / warning / primary / success`), one row of 4 one-tap buttons per §6.5; `aria-label` group for accessibility.
